# Step 5 lightmap + AO bake plan (Palma Builder, 2026-10-30, slice 2 onward)
Status: PLAN. Slice 1 (pbr_world.js, ?pbr=1) ships with no lightmaps. This file covers what the bake slice needs. Source plan: step5-texture-atlas-plan.md §3–§5.

## 1. Tooling on the box (checked 10/30)
- Blender 4.3.2 at /home/box/.local/bin/blender. Run headless: `blender -b -P tools/bake/bake_tile.py -- <tile.glb> <out>`, Cycles CPU, OIDN denoise. No GPU is needed.
- KTX-Software 4.4.2 at v3build/tools/ktx/bin (`ktx create`; env from tools/quest_pipeline.py env()). It encodes lightmaps as UASTC + zstd and AO/alpha as ETC1S.
- Export: page-side THREE.GLTFExporter (r128 examples/js, loaded only by the exporter page, never shipped) from `?seed=1&pbrexport=1`. Seed 1 is the shipping layout (WP_SHIP_SEED=1 in patch_world_perf.py), so a full-city bake is deterministic. That unblocks note §8 of the atlas plan.
- uv2: Blender `Smart UV Project` (angle 66°, island margin 4 px at 1024) or xatlas via the `xatlas` python wheel (pip --user, offline wheel to be checked). Default to Blender Smart UV: one tool, deterministic.

## 2. What gets uv2 / what doesn't
- **uv2 + lightmap:** district asphalt planes (10, 1 quad each, so uv2 = planar xz normalised to the tile), sidewalk/curb strips, plaza, bridge decks/parapets/piers, blockout static areas (beach, underpass, port apron, Dash road), garages and landmarks. These are converted from DET/INST to per-tile merged meshes only if the draw delta is 0. Otherwise they take per-instance AO.
- **Buildings (FACADE instanced boxes, 159):** no uv2. AO is analytic in the facade shader: base darkening exp(-y/2.2) already exists, plus a baked per-instance "sky visibility" float (aSky, sampled at bake time from a 2D height-field ray march around each footprint). The night bounce from the lightmap at the building base comes from the ground lightmap.
- **Instanced props (INST/DET pools: boxes, cyl, palms, lamps, benches, containers):** per-instance AO scalar `aAO` (InstancedBufferAttribute, 1 float). It comes from the ground AO texel at the instance base and a hemisphere ray count against the bake mesh (Blender `ray_cast` from the instance centre, 32 rays). It's applied as diffuse*mix(aAO,1,smoothstep(0,2,localY)) so the contact darkens and the top stays clean. There are no extra draws, and memory is 4 B/instance (about 40 KB total).
- Ground contact under props: the ground lightmap AO already holds props as occluders, since they're exported into the bake scene as occluder-only proxies. No decal draws are needed.

## 3. Tiles and atlas sizes
- Tile grid = the world_perf merge tile. The bake uses 270 m sub-tiles so texel density stays ≥ 4 px/m on the ground.
- Per tile, lightmap = RGB day + RGB night + AO in the alpha of day.

| Area | Tiles | Desktop | Quest | Density (Quest) |
|---|---|---|---|---|
| Portside + plaza, Strip, Cove (hero) | 3 | 2048² | 1024² | ~3.8 px/m |
| Other districts (Yard, Port, Drive, Heights, East, 98) | 6 | 1024² | 1024² | ~3.8 px/m |
| Bridges (causeway, shore, b98) as strips | 1 atlas | 2048×512 | 1024×256 | ~1.5 px/m |
| Garages + landmarks (interiors excluded) | 1 atlas | 1024² | 512² | object-space |

- Quest memory: 10 maps × 2 (day+night) × 1024² × 1 B (UASTC→ASTC 4×4) × 1.33 ≈ 27 MB. That fits the ≈25–30 MB line in atlas plan §4 and the audit's ≤100 MB step-5 headroom (slice 1 uses ≈ 15 MB, see the board).
- Desktop: hero tiles at 2048 add ≈ 11 MB.

## 4. Runtime
- MeshStandard world materials (pbr_world.js) get `lightMap` = day KTX2 plus a `pbrLmN` night sampler. They are lerped by FACADE.uDay in the existing onBeforeCompile (one extra fetch). Quest can use `?lmswap=1` to swap at the dusk midpoint instead.
- Each tile material is cloned per tile only where the tile is already its own draw (world_perf 810 m tiles). Asphalt is 1 merged mesh, so it gets 1 page with all 10 district planes in uv2. That keeps the draw delta at 0.
- Fallback: no lightmap means the slice-1 look. ?toon=1 still forces the old look.

## 5. Order of work
1. Exporter page + seed-1 GLB of ground/bridges/blockout/garages (occluders: building boxes, props).
2. Blender script: uv2, bake day (sun from sky.js day, sky #9ab8e0, 128 spp), night (emissive neon/signs at crew colours + moon fill, 256 spp), AO 0.6 m. OIDN. Export PNG.
3. ktx create (UASTC + zstd 18, mips), then hand to Rydah Optimizer for quest_pipeline sign-off.
4. Write uv2 back. Ground planes use analytic uv2, so no geometry is shipped. Bridge/blockout merged meshes get a uv2 Float32 sidecar (.bin) keyed by mesh name, checked by vertex count.
5. Measure: draws (must be 0 delta), Quest ms with OVR Metrics, memory against the audit.

## Slice 2 notes (2026-10-30 13:30 CDT, in progress)
- Contact shading: started with the cheapest high-impact option. This is a **runtime-baked top-down AO mask**, not the Blender uv2 bake, which stays the long-term plan.
  - At load, building colliders (occluders) and sidewalk/curb rects are drawn into a 1024² luminance DataTexture over the map bounds (~0.8 m/px), then blurred.
  - It is sampled by world xz in the ground shader (1 fetch): it darkens asphalt at wall bases and kerbs, and drives the gutter "damp" mask.
  - Memory is ~1.4 MB (L8 + mips). No uv2 and no draw delta.
- Per-instance/vertical contact AO: injected world materials (INST box pool, bridges) darken by height above ground on vertical faces (smoothstep 0..1.2 m). It is analytic, so there's no attribute and no memory cost.
- Asphalt contrast: macro patches from a second low-frequency fetch of the asphalt tile, a contrast curve, and gutter damp darkening from the AO mask.
- Wet sheen: at night, roughness drops toward .2 in damp gutters and macro "puddle" patches, so the Portside env cube reflects. Day is mostly dry. It stays under the bloom cap.
- Bridges: the bridges.js fine InstancedMesh material, the deck/parapet/joint toon colours, and the pier/concrete INST instances (by colour) go onto the PBR path.
- 14:2x: the bridge deck lives in merged vertex-colour toon meshes (world_perf), so it is converted by vertex-colour match (0x2a2d3a → asphalt tile; concrete colours → concrete tile). Asphalt k .42→.27, env 1.3→.9, macro .6–1.25 (it read too light in the 960 check).
